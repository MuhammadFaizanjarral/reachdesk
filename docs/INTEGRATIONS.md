# Integration capabilities and release boundaries

Reviewed against the official documentation on November 7, 2026. Provider access, review, billing and granted scopes must be checked when configuring a production integration. Saving a social profile URL does not connect an account. Logged outreach is not evidence that a provider delivered a message.

## Evidence and metrics

- Social links are extracted only from actual anchor URLs on the fetched page. They are website-linked profiles, not independently verified ownership and not a claim to find every account. Never infer a profile from a name alone.
- Website tool detection records a recognized script host. It does not prove that the tool's AI features are enabled or that a business appears in AI answers.
- AI visibility needs the engine, query/prompt, date, location and returned evidence. Do not fabricate a score from homepage metadata or confuse readiness with measured visibility.
- Google Business audits need a recorded listing and evidence for each finding. Missing access should appear as unknown, not a failing visibility score.
- Keep drafts, manually logged outreach and provider-confirmed sends distinct. Count unique contacted leads and messages separately in reports.
- Future inbound integrations should verify webhook signatures, deduplicate provider event IDs, associate the authorized account and workspace, then create in-app notifications. Email delivery is not implemented by this core workflow.

## Homepage audit safety and limitations

The calling server route must authenticate the member, authorize access to the lead, and pass the exact saved lead website to `auditWebsite`; it must not accept an independent arbitrary fetch destination. Input is restricted to HTTPS on port 443 with no URL credentials. IP literals (including normalized alternative IPv4 forms), local/intranet names and known local mapping/metadata domains are rejected. Redirects are manually validated and restricted to the exact original hostname. Cross-host redirects require the user to update the saved lead URL. Responses must be HTML, at most 1 MB after reading, and finish within 12 seconds. No user cookies or authorization headers are forwarded.

The Vercel edition also resolves A/AAAA answers, rejects private/reserved destinations, and pins a validated public IP into the HTTPS socket lookup. Each redirect goes through the same check and normal TLS hostname verification remains enabled. Local addresses, metadata endpoints and DNS rebinding must not be allowed to reach internal services. This is separate from the original Worker fetcher's network boundary.

HTML parsing is intentionally lightweight and does not execute JavaScript or fetch images, stylesheets, robots.txt or subpages. The score is a fixed-weight checklist over eight disclosed checks. JSON-LD is checked only for JSON syntax, not schema correctness. HTTP `X-Robots-Tag` and actual search-index status are outside this report. Social and tool findings can be incomplete on client-rendered sites.
